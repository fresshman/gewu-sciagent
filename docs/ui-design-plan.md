# 格物 (Gewu) Web 前端 · 界面设计规格

> 目标：自研一个**轻量 Web 前端**，接入 OpenClaw Gateway API，作为「格物」科研智能体的统一体验入口与参赛演示面板。
> 设计原则：**移动优先 (mobile-first)**、**科研驾驶舱 (research cockpit)** 心智模型、**扁平克制的科学美学**。

---

## 1. 总体定位与核心理念

格物不是"聊天机器人 UI"，而是**科研全生命周期驾驶舱**。区别于普通论文工具，界面要把 7 阶段科研闭环（定方向 → 读论文 → 复现 → 改进 → 写论文 → 发表追踪 → 沉淀）**可视化、可感知**。

**核心原则：手机与 PC 不是同一套内容的"缩放"，而是"分层"。** 手机屏小、注意力碎片化，只呈现**概览与关键结论**（阶段进度、一句话结论、对话摘要）；PC 屏大、用于"坐下来做科研"，呈现**全量细节**（工具入参/返回值、完整图表、5 折 CV 全表、全部文献与子任务）。普通响应式站点只做布局重排，本设计额外做**信息量分级**。

四条设计主线：

1. **设备内容分层（不同设备，不同信息量）**——手机=概览/监控面（工具调用与图表默认折叠/后置）；PC=全量操作面（一切细节内联展开）。详见第 4、8 节。
2. **可见的编排（Visible Orchestration）**——用户能看见 Director 派发给哪个子 Agent、调用了哪个 MCP 工具、处在 7 阶段哪一步。这是参赛"创新性/实用性"最直观的卖点。
3. **科研质感（Lab-grade）**——科学产出是第一类公民，而非聊天附属（PC 全量呈现，手机概览呈现）。
4. **移动优先**——先保证手机端完整可用（单栏 + 底部 Tab + 内容折叠），再向 PC 扩展为三区驾驶舱。

## 2. 前端如何接入 Gateway（架构约束 → 必须套一层轻代理）

**实测结论（决定架构）：**
- Gateway 运行在 `127.0.0.1:18789`，自带 SPA 控制面板；`/health` 返回 `{"ok":true,"status":"live"}`。
- REST API 真实存在（bundle 含 `gateway-client`、`/api/users/`、设备鉴权 `openclaw.device.auth.v1`、`fetch(..., credentials:"same-origin")`）。
- 它是 **loopback-only + 同源鉴权 + 可能需 device auth**。浏览器从 `localhost:3000` 直连 `127.0.0.1:18789` 会被 **CORS** 与鉴权双重拦截。

**因此采用「前端 → 本地轻代理 → Gateway」三层：**

```
浏览器 (Vite/React SPA, :3000)
   │  fetch('/api/...')  同源
   ▼
本地轻代理 (Node/Express 或 Python FastAPI, :3000)
   │  注入 device/auth token，转发 /api/* 到 127.0.0.1:18789
   │  处理 SSE 流式对话
   ▼
OpenClaw Gateway (:18789, loopback)
```

- 轻代理职责：① 托管静态前端；② 反向代理 `/api/*` 到 Gateway 并注入鉴权；③ 把 Gateway 的 **SSE 流式消息**透传为前端 EventSource/stream；④ 统一错误处理与重连。
- 参赛演示：代理可一键 `npm run dev` 启动，本地 `http://localhost:3000` 即为体验链接；对外发布时由部署平台（或内网穿透）暴露代理端口即可，Gateway 始终留在内网。

**技术栈建议（轻量）：** React + Vite + TypeScript；状态用 Zustand；图表用轻量 `uPlot`（光谱/回归曲线高性能）；流式用原生 EventSource / fetch-stream。整个前端 < 200KB gzipped。

**M1 实现注记（已落地）：** 出于"浏览器同源无 CORS"的约束，M1 的本地代理（`web/proxy/server.mjs`，零依赖 Node）采用**官方 CLI 桥接**而非直连 Gateway WS——`/api/chat` 通过 `openclaw agent --agent <id> -m <msg>` 这个 Gateway 官方客户端把对话跑通，再把 stdout 以 SSE 透传。实测稳定可用（已验证 intern-s2 回复）。后续若需"逐字流式 / 可见编排（工具调用、子 Agent 派发）"的完整事件流，可将桥接替换为**直连 Gateway WebSocket**（仪表盘即以此通信，bundle 内含 `gateway-client` 与 `new WebSocket`），届时只需改代理内 `/api/chat` 实现，前端 SSE 消费层不变。

## 3. 信息架构（路由）

| 路由 | 名称 | 移动端形态 | 说明 |
|---|---|---|---|
| `/` | 研究主页 | 单列 | 新建研究、近期会话、进行中课题卡片 |
| `/research/:id` | 研究工作台 | 单列（桌面双栏） | 核心页：左=阶段管线+会话列表，右=对话流 |
| `/research/:id/pipeline` | 阶段管线 | 全屏时间线 | 7 阶段进度、每阶段产出物、可下钻 |

| `/settings` | 设置 | 表单 | 默认模型（intern-s2 等）、Agent 开关、主题 |

## 4. 移动优先布局

**手机端内容策略（概览优先，不是全量缩小）：** 手机屏有限，默认只给"够用的概览"，深入细节留给 PC：
- 7 阶段以胶囊条 + 当前高亮呈现，阶段产出物**不内联**，点击才下钻；
- Agent 回复中的**工具调用卡默认折叠**，仅显示工具名 + 状态 + 一句话结论，展开才看入参/返回值；
- 光谱图、回归曲线等重型可视化**默认不渲染**，以"查看图表 ↗"入口后置，点击再加载；
- 文献/子任务列表只显示前 3 条 + "展开全部"；
- 指标只显示核心 1–2 个（如 R²），其余收进"更多指标"。
目标：让用户**随时掌握研究进度与关键结论**，而非在小屏上硬塞全量数据。

**断点（与主流设备对齐）：**
- `base`：< 640px，手机竖屏，纯单列，底部 Tab 导航。
- `sm`：≥ 640px，大屏手机/小平板，对话区加宽、阶段胶囊换行。
- `md`：≥ 768px，开始双栏：左 320px 管线/会话，右对话。
- `lg`：≥ 1024px，双栏 + 右侧可临时展开"工具/数据"抽屉。

**栅格：** 8px 基准间距（4/8/12/16/24/32）。移动端内容左右留白 16px，最大内容宽度在桌面端限制为 1200px 居中。

**移动端核心页（研究工作台）竖向结构：**
```
┌─────────────────────────┐
│ App Bar: 格物 · 课题名    │  ← 顶栏：返回 + 课题 + 菜单
├─────────────────────────┤
│ 阶段胶囊条 (横向滚动)      │  ← 7 阶段，当前高亮，可点
├─────────────────────────┤
│                         │
│   对话流 (可滚动)         │  ← 用户/智能体气泡、Agent 徽章、
│   含工具调用卡 / 光谱图    │     MCP 工具卡、光谱 sparkline、指标
│                         │
├─────────────────────────┤
│ 底部 Tab: 对话·管线·工具·设置│  ← 移动端主导航
├─────────────────────────┤
│ Composer 输入条          │  ← 文本框 + 发送 + 附件(光谱图)
└─────────────────────────┘
```

**底部 Tab（仅移动端 ≤ md 隐藏为抽屉）：** 对话 / 管线 / 工具 / 设置，图标 + 文字，2px 高亮指示当前。

## 6. 字体方案

**字体栈（无需外部加载，零依赖、首屏快）：**
```
--font-sans: "PingFang SC", "Microsoft YaHei", "Source Han Sans SC",
             "Noto Sans SC", system-ui, -apple-system, "Segoe UI", sans-serif;
--font-mono: "JetBrains Mono", "SF Mono", ui-monospace, "Cascadia Code",
             Consolas, monospace;
```
- **正文/UI**：`--font-sans`（中文优先，西文回退 system-ui）。
- **代码 / 光谱数据 / 指标数字**：`--font-mono`（等宽，数字对齐）。

**字号阶梯（移动优先，rem 基准 16px）：**
| 角色 | 尺寸 | 字重 | 行高 |
|---|---|---|---|
| 大标题 H1 | 20px | 500 | 1.3 |
| 标题 H2 | 17px | 500 | 1.35 |
| 小节 H3 | 15px | 500 | 1.4 |
| 正文 Body | 15px | 400 | 1.6 |
| 辅助 Caption | 13px | 400 | 1.5 |
| 标注 Micro | 12px | 400 | 1.4 |

> 中文界面不用 Title Case / 全大写；中文本身就是天然分词。数字与单位（如 `24.8 MJ/kg`、`R²=0.96`）统一 mono 展示。

## 7. 关键组件规格

1. **阶段胶囊 (StageChip)**：圆角胶囊，7 个阶段横向排列，当前阶段 `--brand` 实心、已过阶段打勾、未到阶段灰显；点击在对话区顶部插入"阶段上下文"。
2. **Agent 徽章 (AgentBadge)**：每个智能体回复带彩色小徽章（探员/复现员/改进员…，用 accent 色区分），一眼看出是谁在答。
3. **工具调用卡 (ToolCallCard)**：可折叠卡片，显示 `mcp__<server>__<tool>`、入参摘要、运行状态（pending/running/done）、返回关键值。这是"可见编排"的核心。
4. **光谱图 (SpectrumChart)**：uPlot 轻量折线，X=波长，Y=强度，支持选区/归一化；用于 LIBS demo 直观展示输入。
5. **指标卡 (MetricCard)**：`--bg-sunken` 底、无边框、圆角；上 13px 灰标、下 24px/500 数字（如 5 折 CV 的 RMSE / R²）。
6. **对话气泡 (MessageBubble)**：用户右、智能体左；智能体气泡左上角 AgentBadge，气泡内可嵌入 ToolCallCard / SpectrumChart / MetricCard。
7. **底部输入条 (Composer)**：文本域 + 发送按钮（带 ↗）+ 附件（上传光谱图触发 `sci_data.parse_figure`）。

## 8. 桌面端布局（科研驾驶舱 · 三区固定布局）

PC 端不是"手机版放大"，而是**横向铺开的科研驾驶舱**：信息密度高、三区常驻、一眼掌控全局。移动端那套底部 Tab 在桌面隐藏，改为左侧常驻导航 + 右侧常驻工具面板。

**PC 端内容策略（全量，不是概览）：** 与手机相反，PC 把"手机里被折叠的一切"都内联展开：
- 工具调用卡**默认展开**，入参、返回值、耗时一目了然；
- 光谱查看器、5 折 CV 全表、回归曲线**常驻右面板**，无需点击加载；
- 文献与子任务完整列表，可排序/筛选；
- 多 Agent 并发时，中栏顶部显示各子 Agent 实时状态与分工。
PC 是"坐下来做科研"的**主工作台**，手机是"路上看进度"的**监控面**——两者信息量刻意不同。

### 8.1 断点策略（补全）
| 断点 | 宽度 | 布局 |
|---|---|---|
| `base` | < 640 | 手机单列 + 底部 Tab（对话/管线/工具/设置）|
| `sm` | ≥ 640 | 大屏手机，对话区加宽、阶段胶囊换行 |
| `md` | ≥ 768 | **双栏**：左 280px 管线/会话 + 右对话；右工具面板改为可滑出抽屉 |
| `lg` | ≥ 1024 | **三区驾驶舱**：左管线 + 中对话 + 右工具面板（常驻）|
| `xl` | ≥ 1440 | 内容最大宽度 1440 居中，右面板可放宽到 400px |

### 8.2 顶栏（App Bar，全断点统一）
左：格物 Logo + 当前研究课题名；中：全局搜索/指令；右：默认模型切换（`intern-s2` 等）、主题切换、账号/菜单。高度 52px，底部 0.5px 描边。

### 8.3 三区布局（≥ lg）
```

│ App Bar: 格物 · LIBS 煤热值预测    [模型▾] [☀/🌙] [≡]          │

```

- **左栏 (280px, 常驻)**：研究空间导航（研究主页/进行中/已归档）→ 当前课题卡片（进度 N/7）→ **7 阶段竖向时间线**（每阶段圆点：✓已完成 / ◐进行中 / ○未开始，点击下钻该阶段产出物与子 Agent）→ 子任务/会话列表。竖向滚动。
- **中栏 (flex)**：顶部阶段胶囊条（与手机一致，横排）→ 对话流（加宽，气泡更大、并排显示多工具卡）→ 底部 Composer（更宽，支持多附件、代码片段、@指定 Agent）。
- **右面板 (360px, 可折叠 ⟩)**：工具/数据面板常驻，分块：① 光谱查看器（uPlot，可缩放/归一化）；② 5 折 CV 指标卡（RMSE/R²/MAE 并排）；③ 文献与产出物列表（可点击跳转）。这是 PC 端差异化重点——把科学产出"钉"在右手边，不占对话空间。

### 8.4 交互增强（仅桌面）
- 左栏阶段时间线点击 → 中栏顶部插入阶段上下文并滚动到该阶段消息；右栏联动显示该阶段产出物。
- 右面板可折叠（⟨/⟩），折叠后对话区占满，给长文阅读留空间。
- 键盘：`Ctrl/Cmd+K` 全局指令；`Ctrl/Cmd+B` 折叠左栏；`Ctrl/Cmd+\` 折叠右栏。
- 多 Agent 并发：中栏顶部可显示"N 个子 Agent 并行工作中"的聚合指示（Director 派发可视化）。

## 9. 动效与可访问性

- 动效克制：仅阶段切换、流式 token 渐显、抽屉滑出；≤ 200ms 缓动；尊重 `prefers-reduced-motion`。
- 流式：对话用 EventSource 接收 Gateway SSE，逐字渐显，显示"某 Agent 正在思考/调用工具"的 typing 指示。
- 可访问性：对比度达标（正文 ≥ 4.5:1）；所有交互元素有焦点环；图标配 `aria-label`；阶段时间线语义化 `<ol>`。

## 10. 实施里程碑（建议）

1. **M1 轻代理 + 骨架 ✅ 已完成（2026-10-22）**：Node 零依赖代理（`web/proxy/server.mjs`）打通 Gateway `/health` 与对话 SSE；React+Vite+TS 空壳 + 三区响应式布局 + 明/暗主题 token 全部落地。已端到端验证：浏览器→代理→`openclaw agent`→Gateway→intern-s2→SSE 回流（`start/delta/done`）。
2. **M2 移动对话核心**：Composer + 对话流 + AgentBadge + ToolCallCard 折叠；阶段胶囊条。
