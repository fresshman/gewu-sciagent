# 结构化提问（AskUserCard）

状态：**前端与解析已实测；agent 侧未接**（网关未启动，见文末「还差一步」）。

## 它解决什么

7-mode 与真值隔离都要求「证据不足就阻断并索要」。但在这次改动之前，agent
只能把问题写进正文——一段散文，用户得自己看懂、自己组织语言回答。于是：

- 问题里的三个选项，用户得复述一遍才能回答，复述里就丢条件；
- 用户不知道 agent 到底在等什么，常常回一句「你看着办」，等于把决定权又扔回去；
- 输入框一直亮着，看起来可以自由聊天，实际上 agent 正在等一个具体答案。

## 格式

agent 在**回答正文之后**追加一个 ```ask 围栏，内容是一个 JSON：

````markdown
表 4 的四个臂我都跑完了。先定一件事再往下写：

```ask
{
  "question": "第 5 折的 OOF 预测按哪种口径复算？",
  "why": "两种口径的 RMSE 差 3.1%，选错结论会反号",
  "multi": false,
  "options": [
    { "label": "合并 OOF", "desc": "70 条预测一次性算 RMSE" },
    { "label": "5 折均值", "desc": "先算每折再取平均" },
    { "label": "两种都算", "desc": "多花 40 秒，用于附录对照" }
  ]
}
```
````

| 字段 | 必填 | 说明 |
|---|---|---|
| `question` | 是 | 一句话说清要定什么。空则整块作废 |
| `why` | 否 | 为什么这件事必须由用户定。写不写都行，但没有它用户没法判断 |
| `options` | 是 | 至少 2 个、最多取前 8 个。少于 2 个不算选择题，整块作废 |
| `options[].label` | 是 | 选项正文，也是用户回答时回填给 agent 的那句话 |
| `options[].desc` | 否 | 一行代价/后果说明 |
| `multi` | 否 | 只有显式 `true` 才是多选。写 `"true"` 字符串不算 |

## 渲染规则

- 问卷渲染在**消息气泡内**，正文照常走 Markdown（围栏被摘掉，不会漏出 JSON）。
- **最后一条** agent 消息里有未回答的问卷时，输入框换成一条「请先回答上方的问题」。
  这是为了挡住「以为还能自由聊天」的误解。
- 回答后，用户那句话就是一条普通 user 消息——前端不另存「已回答」状态，
  靠「这条消息之后有没有 user 消息」判断。两处各存一份必然对不上。
- 历史里没被回答的问卷显示为「未回答（这一问已跳过）」，并且**不给可点的按钮**。
  看着能点、点了没反应，比不给按钮更糟。

## 键盘

卡片挂载即拿焦点，不用先点一下。

| 键 | 行为 |
|---|---|
| `↑` `↓` `←` `→` | 移动停留项 |
| `Space` | 选中当前项（多选可反复开关）|
| `Enter` | 单选：直接提交当前项；多选：提交已选 |
| `1`–`9` | 直选对应项（只选中，不提交——多选里连按 `1` `2` 是常规动作）|

## 为什么不做阻塞式工具调用

参考项目是「agent 调 `ask_user` 工具后原地等 HTTP 回填」。我们没这么做：

我们的链路是 `web → proxy → CLI 子进程`。工具在子进程里阻塞时，用户一旦关掉
标签页、换台机器、或者浏览器崩了，答案永远不来，整轮对话就死在那儿，而且没有
可续的通道（run 恢复只能重跑，不能补一个答案给等待中的工具）。

所以退一步：agent 照旧结束本回合，只把问题写成结构化块；用户点选的结果当作下一条
普通消息发回去。代价是多一次 LLM 往返，换来的是**永远不会卡死**。

如果以后真的要做阻塞：得先有「待答问题」的持久队列 + 超时降级（超时后 agent
收到 `timeout` 继续跑而不是报错）+ 断线重连能把问题重新挂出来。三样缺一不可。
