# 价值、边界与成本

> 写作时间：2026-11-10 · 对应提交见本文件末尾
> 本文回答三个评审必问、而此前 README 没有正面回答的问题：**谁会用**、**比现在强在哪**、**一次多少钱**。
> 所有数字都标了来源；凡是没有实测支撑的，一律写「假设」或「未验证」，不写成结论。

---

## 0. 一句话定位

**格物不替人做科学发现，它把「一次可复现的课题」从「几周手工串联」压成「一条命令 + 两个人工审查门」，
并让稿子里的每个数字都能当场重算。**

这个定位比「通用 AI 科学家」低，但它是**可交付**的：仓库里每一个数字都有 source_of_truth，
`rerun_experiment` 会真跑脚本并对不上就报 drift。反过来，我们**没有**「自主提出新假说 → 闭环验证」的能力，
这一点在 [`docs/comparison.md`](comparison.md) 里与 Kosmos / Robin / AI Scientist v2 逐项对照，不掩饰差距。

## 1. 谁会用（三个角色，各自的触发场景）

| 角色 | 真实触发场景 | 格物在这一步具体做什么 | 已有证据 |
|---|---|---|---|
| **在读研究生（有数据、缺工程时间）** | 手上有一批**未发表**的 LIBS / 近红外光谱和热值或理化指标，需要出 5 折交叉验证、消融表、图和一份能投的初稿骨架 | 复现基线 → 跑消融 → 出图 → 按期刊模板成稿；数字全部从 `summary.json` 取，不手抄 | 5 折 `RMSE 214.57 ± 25.71 kcal/kg`、`R² 0.896`、vs PLSR 基线 **8.28%**；20 折组件级消融（127 min CPU） |
| **课题组 PI / 博后（要复用、要审计）** | 学生毕业交接，半年后没人能说清「论文里那个 214.57 是怎么来的」 | 每个实验登记 `rerun` 规范；`rerun_experiment(id)` 现跑现比，超容差报 **drift** | `gewu/mcp/registry/coal_mil.json` 21 条 + 第二领域 3 条；`tests/test_domain_registry.py` 锁住「重算必须一致」 |
| **企业研发 / 质检（数据不能出内网）** | 光谱与配方是资产，不允许上传任何云 | 领域模型走**路径引用**：权重 `.pt` 与原始谱留在原项目目录，格物按 `COAL_PROJECT_ROOT` 运行时读取 | README「真实领域推理 + 未发表成果零外泄」；`.gitignore` 排除 `output/documents/`、`data/raw/` |

**共同点**：三类人手上**都已经有数据**。格物解决的不是「没数据怎么办」，而是「有数据但把它变成可复现、可审计、
可投稿的东西太费人」。

## 2. 比现在强在哪（与「手工」和「通用 LLM 聊天」逐项对照）

「现在」指两种常见做法：**(A) 手工跑脚本 + 手抄进稿**，**(B) 直接把数据丢给通用大模型让它写**。

| 环节 | A. 手工 | B. 通用 LLM 直接问 | 格物 | 证据 |
|---|---|---|---|---|
| 基线复现 | 1–3 天对齐脚本、环境、随机种子 | 做不到（不执行代码） | `run_min_case.py` 一条命令，**十层 72 项校验**，冷启动实测 5.5 s（内部计时 3.69 s） | `docs/verification/2026-11-09-min-case.md` |
| 数字与稿子一致 | 手抄，改一次实验就漂 | 生成时好看，但数字**无法与产物对账** | claim 审计把稿中声明与注册表/`summary.json` 对照，不一致直接标红 | `scripts/e2e_smoke_test.py`（指纹比对抓出过真实漂移） |
| 消融结论 | 常写成「有效」但不做统计检验 | 会顺着你的话编「显著提升」 | 配对 t + 95% CI + 留一折 + 杠杆比；本轮结果是**未检出**（p=0.294/0.393/0.580），于是如实写「未检出」 | `docs/verification/2026-11-09-component-ablation.md` |
| 图 | matplotlib 反复调样式 | 只能给代码，不能出图 | 17 个绘图工具 + 三组消融各自归一 vMax | `gewu/mcp/sci_plot.py` |
| PDF 编译 | 本机缺 TeX，中文常整段丢失且退出码为 0 | 不涉及 | 接 tectonic，两篇真实论文 **0 error / 0 缺字 / 0 overfull** | `docs/verification/2026-11-09-pdf-pipeline.md` |
| 换领域 | 重写整套脚本 | 无需改，但也不执行 | 换注册表 + 脚本即可，**引擎零改动**（已用第二领域验证） | `docs/verification/2026-11-10-domain-generality.md` |
| 成本 | 人力 2–4 周 | 按 token 计，但**产出不可核** | 一次完整链路 **0.26–3.0 元**（见 §3），本地算力 0 元 | `docs/verification/cost_audit.json` |

### 明确不如的地方（不写会显得像吹）

1. **不会自己提新假说**。假说由人给；本仓没有「探索 → 发现 → 验证」闭环。Kosmos / Robin 有，我们没有。
2. **真实领域只验证过 2 个**（煤 LIBS 光谱、临床表格），其中只有 1 个是光谱类。**光谱以外的迁移未验证**。
3. **不接湿实验**：不做仪器控制、不做实验设计，也不声称能做。
4. **中文期刊排版细节仍需人工收尾**：模板能给骨架，编辑部格式要求千差万别。
5. **没有托管 CI**：只有本地等价门禁（`scripts/verify_all.py`），不假装有自动流水线。

## 3. 一次多少钱（可复算，不是拍脑袋）

方法：用 `tiktoken` 对**真实落盘产物**分词，乘公开牌价。脚本 `scripts/cost_audit.py`，
产物 `docs/verification/cost_audit.json`，随时可重跑。

| 项 | 数值（o200k / cl100k 两种分词器） | 性质 |
|---|---|---|
| 7 阶段 handoff 产出 | 16,799 / 18,873 tokens | **实测**（对真实 JSON 分词） |
| 论文正文 `main.tex` | 13,008 tokens | **实测** |
| 阶段输入（技能文档 + 上游 handoff） | 84,136 / 99,550 tokens | **重构下界**（不含系统提示、工具 schema、会话历史） |
| 本地算力 | **0 元** | 全部在自备 CPU 上跑（torch CPU / sklearn / tectonic），无租卡；电费未计 |

按公开牌价折算（一次完整课题，仅成功链路）：

| 模型 | 单价（元/百万 tokens，输入/输出） | 一次成本（仓库内，含论文存档） | 一次成本（干净 clone，无存档） | 来源 |
|---|---|---|---|---|
| DeepSeek-V4-Flash（空闲） | 1.5 / 4.5 | **0.26–0.30 元** | **0.23–0.26 元** | 央视财经转述官方调价（2026-08-17） |
| DeepSeek-V4-Flash（高峰） | 3.0 / 9.0 | 0.52–0.60 元 | 0.46–0.53 元 | 同上 |
| DeepSeek-V4-Pro（空闲） | 4.5 / 13.5 | 0.78–0.90 元 | 0.69–0.79 元 | 同上 |
| 含返工（×3 / ×10，**假设**倍数，仓库内） | — | 0.78–0.90 / **2.60–3.00 元** | 2.29–2.63 元（×10） | 倍数是假设，仓库无重试埋点 |

**为什么有两个数**：论文 `main.tex` 按设计不入库（属未发表成果），干净 clone 里少了这 13,008 tokens 的交付物，
成本随之下移。两个数都是实测，差别是**环境**而不是口径 —— 这点必须写出来，否则评审 clone 下来一跑，
看到的 0.23 会和文档里的 0.26 对不上。

**三条必须一起读的口径**：

1. 这是**下界**：输入侧真实 prompt 比重构值大，且**未计重试**。给 ×3 / ×10 敏感性是因为一次真跑必然有返工，
   但返工次数仓库里没有埋点，所以只能给区间，不能给「准确值」。
2. **本机无 API key**，无法给出账单级实测。这是「公开牌价 × 真实产物用量」的复算，**不是账单**。
3. **不要拿这个数字和 Kosmos 的 $200/次 比性价比**：它做的是 12 小时自主探索（4.2 万行代码、1500 篇文献），
   我们做的是一条**已有人工设定目标**的可复现链路。任务范围不同，单价不可比。
4. **分词器编码表首次需联网**（约 1 MB）才能本地分词；断网且无缓存时 `cost_audit.py` 不可用，
   但**不影响**测试与主链路（它只是审计脚本）。

## 4. 不适合谁（反向筛选，省双方时间）

- 想「一句话生成一篇 Nature」的：本仓的目标是**可复现**，不是**可发表**，更不是**可发现**。
- 手上没有任何实验数据的：无米之炊，会退化成跑合成数据。
- 需要控制仪器 / 设计湿实验的：没有这个能力。
- 要求全自动无人值守的：流程里有**两个强制人审门**（方向确认、投稿前终审），这是设计而非缺陷。

