# 第二真实领域取证：换学科，引擎零改动

> 时间：2026-11-10 · 触发问题：评审指出「领域泛化仅 1 例，不足以支撑『通用』」
> 结论先说：**机制泛化成立（已实测）；方法泛化不成立（未验证）**。两者不能混为一谈。

---

## 1. 为什么之前只有 1 例，以及为什么补这一例

此前台账里只有 `coal-mil` 一个**真实**领域，另有一个 `demo_synth` 合成域。
合成域证明不了泛化——它本来就是为跑通链路而造的。评审的判断是对的。

补的这一例必须满足三个条件，否则等于又造一个合成域：

1. **真实数据**，且第三方能拿到同一份（可核对指纹）；
2. **数据结构与目标量纲都和煤域不同**（否则只是换个文件名的同一件事）；
3. **引擎零改动**（否则证明不了「机制与学科无关」，只证明了「我们又写了一套」）。

选 **UCI Diabetes**（Efron et al. 2004，随 scikit-learn 分发包离线提供）：
442 样本 × 10 项临床基线指标，回归目标是疾病进展指数（25–346）。
它是表格数据、不是光谱；量纲是疾病进展指数、不是 kcal/kg。三个条件都满足，
且**不需要联网、不需要申请数据**，任何人 clone 下来就能复现。

## 3. 实测结果（5 折，seed=42，`KFold(shuffle=True)`）

| 臂 | RMSE | MAE | R² | 折内 RMSE |
|---|---|---|---|---|
| `ols`（标准化 + 线性） | **54.85 ± 2.64** | 44.27 | **0.4785** | 53.85 / 51.60 / 57.55 / 52.90 / 58.34 |
| `pls`（标准化 + PLSR 5 成分） | 54.86 ± 2.43 | 44.25 | 0.4787 | 53.78 / 51.97 / 57.60 / 53.03 / 57.90 |
| `ridge_poly2`（二阶交互 + RidgeCV） | 55.65 ± 2.31 | 44.70 | 0.4669 | 51.47 / 55.48 / 58.31 / 55.86 / 57.11 |

**负向对照**（打乱目标后重跑 `ridge_poly2`）：RMSE **77.35**、R² **−0.0158**。
R² 落在 0 附近说明流程**没有**把标签漏进特征侧；这也是本域唯一能自证的「不泄漏」检查。

**多种子稳定性**（10 个种子，仅作稳定性，不进台账）：

| 臂 | RMSE 均值 ± 标准差（10 种子） |
|---|---|
| `ols` | 54.89 ± 0.22 |
| `pls` | 54.97 ± 0.25 |
| `ridge_poly2` | 56.15 ± 0.62 |

---

## 4. 一个必须写下来的负面结论

煤项目上的经验是「**特征增广 + 强正则**能带来增益」。把它原样搬到本域，
`ridge_poly2` 反而比最简单的 `ols` **差 0.80 RMSE**（10 种子均值 56.15 vs 54.89），
且折间方差并没有变小到能补偿这点损失。

所以：**「增广红利」没有跨域迁移**。这条不写，读者会以为格物的方法是通用的；
写了才是真实情况——**方法要按领域重选，能复用的只有机制**。台账里该臂的 `note` 已如实标注。

另一条次要观察：`ols` 与 `pls` 差 0.008 RMSE，统计上等价。**不得**据此宣称 PLSR 在本域有优势。

## 5. 机制验证：引擎真的能重算这个域

三份 registry 条目（`gewu/mcp/registry/clinical_diabetes.json`）都是 `realizable_by_gewu`，
即引擎必须**真跑脚本**再比对，而不是只读台账。

| 实验 id | `rerun_experiment` 状态 | 三项指标 abs_diff（rmse_mean / rmse_std / r2_mean） |
|---|---|---|
| `clin_ols_baseline` | **reproduced** | 4.1e-05 / 6.0e-06 / 3.0e-05 |
| `clin_pls` | **reproduced** | 1.1e-05 / 2.3e-05 / 4.0e-05 |
| `clin_ridge_poly2` | **reproduced** | 4.0e-06 / 1.7e-05 / 1.7e-05 |

偏差量级 1e-5 来自台账里指标保留 4 位小数，不是计算漂移；容差设 0.01 / 0.001，远宽于此。

**引擎零改动的证据不是「我没动」，而是结构性的**：`tests/test_domain_registry.py` 里有一条
`test_engine_stays_domain_agnostic`，断言 `sci_exp.py` 源码中不出现 `diabetes` / `clinical` /
`coal_libs` 等任何领域专属词 —— 一旦有人把学科名写进引擎，测试立刻失败。

## 6. 边界（不许过度外推）

1. **只验证机制泛化**：注册表加载、脚本重算、容差比对、漂移报警四条链路换学科可用。
2. **未验证方法泛化**：没有在第二领域跑 7 阶段 LLM 链路，也没有把 LIBS 的方法搬过去跑通。
   「格物能自动做临床研究」这句话**不成立**。
3. **不是光谱迁移**：这是表格回归。光谱 → 光谱的跨仪器/跨样品迁移**完全没有验证**。
4. **领域总数仍是 2 个真实域**（煤、临床）+ 1 个合成域。距「通用」还很远，
   只能说「不是只有一个例子」。

## 7. 复现命令

```bash
# 三臂 + 负向对照，秒级
python scripts/run_domain_diabetes.py

# 10 个种子的稳定性（不进台账，只作稳健性参考）
python scripts/run_domain_diabetes.py --repeat 10

# 重新生成台账（含脚本 sha256 与 commit 锚点）
python scripts/run_domain_diabetes.py --repeat 10 --ledger docs/verification/domain2_diabetes.json

# 引擎重算（等价于 MCP 工具 rerun_experiment）
python -c "import sys;sys.path.insert(0,'gewu/mcp');import sci_exp as E;print(E.rerun_experiment('clin_pls')['status'])"

# 本域相关测试（6 条）
python -m pytest tests/test_domain_registry.py -q
```

台账文件：[`domain2_diabetes.json`](domain2_diabetes.json)。数字若与当次输出不符，以当次输出为准。
