## 一、为什么补这一条

此前"可复现"的证据链是**对已存档产物做一致性检查**（`scripts/e2e_smoke_test.py`），
而评审要的"可复现"是**从零跑通**。真实课题依赖未发表数据与权重，评审机器上必然缺失，
这使"成果可复现性"始终悬空。

本课题用合成光谱补上另一半：数据在本地生成、模型只用 `numpy + scikit-learn`（不需要 torch）、
`pip install -r requirements.txt` 之后一条命令约 2 秒跑完七阶段。两套叙事分工明确：

| | 真实课题（coal_mil） | 最小课题（demo_synth） |
|---|---|---|
| 证明什么 | 方法在真实 LIBS 数据上有效（214.57 kcal/kg） | 链路能从零自主跑完、数值可复算 |
| 依赖 | 外部私有项目 + 5 折权重 + torch | 无（纯生成） |
| 评审能否执行 | 否（缺私有资产） | **是** |
| 数值可比性 | — | **禁止与真实课题并列比较** |

## 三、生成机制（刻意让 MIL 才有优势）

每个 bag 有 K 个颗粒实例，实例光谱
`x_i = a_i·[b + Σc_k·p_k]·(1+ε_i) + n_i`，其中 `a_i = 1 + h·z_i`：

* `c` 成分 —— 逐实例可见；
* `h` 颗粒异质性 —— **仅 bag 级隐变量**；
* 标签 `y = 3000 + 1200c₀ + 900c₁ + 600c₂ + 1100h + N(0,25)`。

关键性质：`mean(a_i) → 1`，袋均谱几乎抹去 `h`（残留 ∝ h/√K）；而 `max(a_i)` 保留上尾。
因此"先平均再回归"必有系统性损失，实例级定标 + 上尾统计量能补回来。
该机制与真实场景的物理直觉一致（少数粗颗粒主导信号、袋均后信息被稀释），
但**它是被写死的公式**，所以本课题能证伪假设，不能代替真实数据。

## 四、实测结果（70 bag / 611 实例 / 5 折，种子 20261109）

| 臂 | RMSE 均值 (kcal/kg) | 总体 std | R² |
|---|---|---|---|
| 袋均谱 PLSR 基线 | 150.44 | 13.15 | 0.611 |
| MIL 逐实例定标 + LSE 池化 | 122.79 | 12.24 | 0.741 |
| MIL + 强度上尾残差（本方法） | **73.03** | 10.17 | **0.911** |

* 相对基线降低 **51.46%**；
* 逐折配对 t 检验 `t(4) = -22.48`、`p < 0.0001`，95% CI `[-86.97, -67.85]`，五折方向一致；
* Wilcoxon `p = 0.0625`（n=5 的最小可达值，本身不显著）——**两种检验结论一并报告**；
* 文献 3/3 由 arXiv / CrossRef 核验通过，幻觉率 0。

### 假设是预注册的

阶段①把假设写成可证伪形式（判据：`p<0.05` 且五折同向），阶段④按同一判据判定并写入
`handoff_4.hypothesis_verdict`。**判据不因结果好坏而修改**——这是防止"先看结果再编故事"的关键。

### 口径

per-fold 均值（每折各自算 RMSE，再取均值/总体 std ddof=0）为主口径；合并 OOF 仅作补充并显式标注。
本项目已知的 P0-2"指标漂移"就是口径混用造成的，这里在 `summary.json` 里同时存两种并声明。

### β 是诚实的

内层 CV 选出的 β 为 `[0.0, 0.25, 0.25, 0.25, 0.25]`——接近均值池化。
因此报告不宣称"LSE 高阶池化带来增益"，而写"增益来自逐实例定标与上尾残差"。
若为了叙事强行取 β>0，就属于改模型迎合结论。

## 五、十层校验（`gewu/demo/verify.py`）

1 产出完整 / 2 阶段串联 / 3 状态合法 / 4 数值一致（从 predictions 重算）/ 5 无矛盾 /
6 论文自洽（LaTeX lint，含 CJK 支持与 Markdown 残留检查）/ 7 溯源完整（claims 的 JSON Pointer 逐条解析）/
8 **确定性重跑** / 9 注册表与 summary 一致 / 10 **PDF 成品**。

当前 **72 项检查全部通过**。两层是后加的关键层：

- 第 8 层用同一种子重跑 5 折，逐折 RMSE 必须逐位一致——否则"可复现"只是说法；
- 第 10 层核对 PDF 是否真存在且可解析、正文是否含本次关键数值、`docs/paper` 入库快照
  的内容指纹是否与本轮编译一致（防止模板改了而快照悄悄过期）。

`tests/test_min_case.py`（22 用例）含 **12 条负向测试**：篡改 summary 数值、断链、
假称"已核验"、claim 值与源不符、pointer 悬空、删 bibitem、注册表漂移、谎称产物缺失、
PDF 损坏、PDF 缺关键数值、快照过期、编译失败却登记为成功。
校验器若抓不出这些，就等于橡皮章。

## 七、本次踩到并修掉的两个真 bug（留档以免复用错误经验）

1. **参数拼写导致"调参"根本没生效**：探索时把 `COEF_HETEROGENEITY` 写成 `COF_...`，
   赋值只是新建了一个属性，模型仍在用旧常数。教训：调参必须回读模块属性确认生效，
   否则会把"随机波动"当成"调参效果"。已改为按正确名称重做扫描，并在多组参数下验证
   提升幅度稳定（46–53%），排除幸运种子。
2. **核验结果字段名不匹配**：`verify_papers` 输出用 `papers`，解析器读 `results`，
   导致 3/3 通过却被判为 `partial`。降级逻辑本身是对的（宁可不宣称），但解析必须对齐。
   教训：跨模块解析外部 JSON 时，字段名要显式兼容并写进测试。
