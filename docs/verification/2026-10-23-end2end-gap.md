# 端到端走查：格物全流程 + UI 交互缺口清单（2026-10-23）

走查方式：以用户真实的“MIL + LIBS 大颗粒原煤热值预测”课题为载荷，按格物 7 阶段
实际跑一遍（检索 → 反幻觉 → 原页理解 → 领域建模 → 绘图 → 成稿），并在成稿环节
要求 LaTeX 与 Word 双格式产出。**未发表的模型、数据与论文本体始终留在用户本机
原始目录，仓库内仅保留方法与结论。**

## 二、缺陷清单（按严重度排序）

### P0-1 实验链路不可重现 → ✅ 已修（建成**通用实验注册表**，领域无关）
原问题：模型只能对存档最优配置做推理，无对应权重/日志的实验数字无法复现，
只能弃用或标注不可复现（如草稿里的 197.99 kcal/kg）。

**修复方式（关键：做成了通用机制，而不是煤热值专用）**：
- 新增**领域无关的通用引擎** `gewu/mcp/sci_exp.py`（`sci-exp` MCP Server，4 个通用工具
  `list/get/rerun/audit`）。引擎不认识任何学科，只理解一份通用 registry schema
  （id/name/category/config/metrics/source/source_of_truth/reproducibility/rerun）。
- **领域包（如 coal-mil）只需提供**：(a) 自己的计算脚本 `coal_infer.py`；
  (b) 一份 `gewu/mcp/registry/coal_mil.json` 描述其实验与「如何重算」（CLI 重算规范
  + key_map 指标映射 + tolerance 一致性阈值）。接入新学科（蛋白折叠/气候/基因组…）
  **零改动引擎**。
- `rerun` 支持两类：`realizable_by_gewu`/`verifiable_via_summary` → 真跑领域脚本并交叉校验；
  `requires_original_script` → 不复制数据，仅登记+诚实标注复现路径（杜绝 197.99 式无源数字）。
- 每次 rerun/audit 锚定格物仓库当前 commit（代码版本可追溯）。

**实测**：`rerun our_hybrid`（5 折真推理）与 `rerun plsr_baseline`（读 summary）均
`all_consistent=true`，交叉校验差 ≤2.4e-05；`audit` 17 实验 n_drift=0。
测试 `tests/test_sci_exp.py` 用**合成 registry**（不依赖 coal）验证引擎与学科彻底解耦。

### P0-2 指标口径未登记，同一数字在多个文件中漂移 → ✅ 已修（由 audit 工具覆盖）
实测 MIL 直接预测有 347.55 与 633.19 两个版本；PLSR 标准差有 17.95 与 20.07
（总体/样本标准差差异，非错误但极易误用）。

**修复**：注册表是论文所有被引用数字的**单一台账**，每个指标都有其 source_of_truth；
`rerun`/`audit` 一律以「领域脚本真实输出」为准做交叉校验，手抄漂移（如 rmse_mj_mean
0.8979 被运行时算出的 0.8978 覆盖）会被自动检出。双标准差口径由原始项目 summary.json
统一，不手抄。

### P1-1 反幻觉链缺 OpenAlex 层（会议论文被误判） → ✅ 已修
Ilse 2018（ICML，arXiv 1802.04712）在 arXiv/CrossRef/S2 三层下均落到 `unverified`，
但论文真实存在——OpenAlex 一次即命中（实测 `openalex_title_ratio=1.000`，arxiv 1802.04712）。
会议论文（ICML/NeurIPS/CVPR）在 CrossRef 覆盖不足，会造成大量**假阴性**，反而削弱校验的可信度。
→ **修复**：`verify_papers.py` 加 OpenAlex 为第 4 层（标题检索）+ 第 2.5 层（exact-DOI 回退），
核验链变为 `arXiv→CrossRef→S2→CrossRef标题→OpenAlex`；并新建 `verify_server.py`
（FastMCP 服务 `sci-verify`，已注册进 openclaw.json 模板与运行配置），使 7 个智能体
任一可直接调用，反幻觉从"一条会被遗忘的 CLI"升级为**系统级第一公民服务**。
回归测试 8 passed（含 Ilse 2018 真网命中 + 编造标题被拒）。
详见 `docs/verification/anti-hallucination.md`（格物反幻觉横向架构）。

### P1-2 中文文献完全无法自动核验
《光学学报》《光谱学与光谱分析》等中文期刊未被 CrossRef/OpenAlex 收录，校验链
只能标注“待人工核验”。本次论文中 2 条中文引文即处于该状态。
→ 建议：明确降级策略（标记 UNVERIFIED 而非静默通过），有条件时接 CNKI/万方或
用人工核验清单。

### P1-3 草稿中检出一条无法核实的引用（校验链立功）
原草稿参考文献 [5]“Attention-based multi-instance learning for quantitative analysis
of mineral LIBS spectra”在 S2、CrossRef、OpenAlex 三源均无匹配，**高度疑似不准确引用**。
已替换为可核验文献（Energies 2024 煤质 LIBS 综述等）。
→ 提示：投稿前应对**全部**引文跑一遍校验，尤其是“凭记忆写下的”条目。

### P1-4 `office-word` MCP 粒度过细，长文档成稿不可用
54 个工具均为“加一段/插一表/插一图”级别；一篇含 88 段、3 表、6 图的中文论文需要
数百次往返。本次实际用同栈 python-docx 一次性生成。
→ 建议：补一个**批量成稿工具**（接受结构化 JSON：标题/段落/表/图/参考文献），
这才是“论文产出”环节真正需要的粒度。

### P1-5 LaTeX 与 Word 两套内容靠人工同步，必然漂移
本次双格式分别生成，内容等价但无自动一致性保证；任何一处改动都要改两遍。
→ 建议：单一结构化源（JSON/YAML 或 Markdown + 数据绑定）→ 分别渲染 tex 与 docx，
并把“双格式一致性检查”做成测试。

### P2-1 绘图产物与文档引用脱节
`sci-plot` 输出文件名带时间戳（`fig5_methods_rmse_20261023-113232.png`），
LaTeX/Word 中需手工写死文件名，改名即断链。
→ 建议：稳定命名 + 图清单（已有 `list_figures`）与图注注册表联动，
成稿时自动注入 `\includegraphics` 与图注。

### P2-2 Web 前端右栏为纯占位，真实数据无落点
`web/src/components/RightPanel.tsx` 三个区块（光谱查看器 / 5 折 CV 指标 /
文献与产出物）均为 placeholder，源码注释写明“待接入测试案例后启用”。
本次走查恰好产生这三类真实数据（光谱、逐折指标、文献核验表、LaTeX/Word 产物），
但 UI 上无处呈现。
→ 建议：以本次课题为首个真实案例接入（proxy 增加 `/api/metrics`、`/api/figures`、
`/api/artifacts` 三个端点）。

### P2-3 缺少端到端冒烟测试
`tests/` 目前仅有 `verify_papers` 的回归测试；检索→核验→推理→绘图→成稿
没有一条链路级测试。
→ 建议：加一条“最小课题”冒烟（可用公开数据），保证任一环节改动不会悄悄断链。

## 四、论文本身的口径决策（重要）

成稿论文**只采用可复现数字**：

- 采用：5 折折均 RMSE 214.57 ± 25.71 kcal/kg（PLSR 233.95 ± 17.95），
  合并口径 R² 0.9204 / MAE 177.78，均由 `sci-exp` 经 `coal_infer` 对存档模型逐折复算，
  与存档偏差 1.1×10⁻⁵ kcal/kg（见 `rerun our_hybrid` / `rerun plsr_baseline`）。
- 弃用：草稿中的 197.99 ± 23.87（多编码器集成）——当前存档无对应权重与日志，
  无法复现。**通用复现机制（P0-1 的 `sci-exp` rerun）已就位**：未来只要把该实验的
  权重/训练日志纳入版本化、并在 `registry/coal_mil.json` 登记一条 `realizable_by_gewu`
  实验（配上重算命令），即可一键复现，无需为煤热值改写任何引擎代码。
