## 图纸台账（提交 53854a9，只推 Gitee）

从「论文库/写作台」继续往下做的一层：图表原来根本不成账。

**做法**：
- `gewu/mcp/fig_meta.py`（新）：出图时写 `<base>.meta.json`。tool 取调用栈帧（传参可乱写），
  数值入参只留 shape+sha256+极值（光谱几万点 + 未发表数据），`draw` 从渲染完的 Figure
  反读 series 指纹（line→get_xydata / collection→offsets / patch→矩形几何 / image→array）。
- `figure_index.mjs`（新）：按内容 sha256 合并副本，母版取 pdf，id=`fig-<sha8>`；
  `\includegraphics` 按 basename 对到「图 N/§/行号/…」，旁文件只在母版同目录找。
- 前端「图纸」tab（#figures）+ 写作台资产「图纸」+ 图 N 详情挂图纸卡。

**顺手修的三个真 bug**（都不是这次引入的）：
1. `_save` 同一秒画两张同名图 → 后一张覆盖前一张（批量出图必踩）。撞名加序号。
2. PDF 内嵌秒级 CreationDate → 同数据重画字节不同 → 内容寻址的 fig_id 每次都变，
   台账会把一张图记成好几张。`metadata={"CreationDate": None}` 后两次渲染 17660 B 一致。
   这条也让我原来那条「同数据同 fig_id」的测试变成假通过（同一秒内才成立），已改成隔 1.05s 重画断言。
3. `list_figures` 用 `Path.suffix` 判 `.meta.json` → 永远拿不到（suffix 只认最后一段），
   恒报「0 张带出处」。改 `name.endswith`。

**演示**：用表 4 的真实四臂数字（215.75/227.44/226.30/218.13，yerr 34.59/18.83/15.69/29.32）
新画了一张 `coal_ablation_arm_rmse_20261110-113131`（`fig-04195aa1`），它是台账里唯一
有出处的一张，也顺带演示「未引用」状态。文件在用户项目 output/figures 下，不喜欢可删。

## 六条借鉴落地（e9cb335 / b57b527，已推 Gitee）

用户给了 6 条「可借鉴项」，逐条实施并实测。**实测推翻了一个前提**：用户说
「claims.json 12 条都带 registry 来源，正好做成可点跳转」——实际送进 D2 引擎，
能溯源的只有 4 条，7 条 source 前缀引擎不认（写成 `registry:coal_mil#our_hybrid.metrics.x`
把 domain 当实验 id），1 条指标没登记。而论文库当时给这行挂的是绿色「已核」，
依据只是「每条都有 source 字段」。这条假绿是整轮改动的起点。

**已做**：①Markdown 渲染 + 引用 pill（无依赖自写，输出 React 元素而非 HTML 字符串）
②消息内执行行 ActivityRow（runSteps 原先是全局一份，发第二条消息即清空）
③声明核查台 ClaimBoard/ClaimCard（判定权唯一归 Python 引擎，Node 只透传）
④结构化提问卡 AskUserCard（**没做阻塞式 tool**，见下）⑤任务圆环 TaskOrb ⑥`.githooks/pre-commit`
+ `core.hooksPath`（不用 husky：根目录没 package.json）+ `docs/bug_fix/`

**关于 ④ 的关键决策**：参考项目是 agent 调 `ask_user` 工具后原地等 HTTP 回填。
我们的链路是 web → proxy → CLI 子进程，工具在子进程阻塞时用户关掉标签页就永远没有
答案，整轮死在原地且没有可续通道。所以改成「agent 结束本回合，把问题写成 ```ask JSON
块，前端渲染成问卷，答案作为下一条普通消息发回」。代价多一次往返，换来不会卡死。
**agent 侧提示词没改**——网关未启动，改了也无法验证模型是否照做。
格式与要加的那段话写在 `docs/design/ask-user.md`。
